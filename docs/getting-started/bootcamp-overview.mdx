# Bootcamp Overview

A full breakdown of both days — what's covered, when, and what you'll walk away with.

---

## At a Glance

| | |
|---|---|
| **Duration** | 2 Days |
| **Hours** | 9:00 AM – 4:00 PM each day |
| **Format** | Theory + Hands-on Practicals |
| **Batch Size** | Max 20 students |
| **Final Output** | Working Physical AI system + documentation |

---

## Workshop Schedule

| **Day** | **Session** | **Type** | **Description** |
|---|---|---|---|
| **DAY 1 — Foundations of Physical Intelligence** | Session 1 — Introduction to Physical AI | Theory | What is Physical AI? How does it differ from software-only AI? Sensor → Model → Decision → Actuator architecture. Real-world examples and why it matters now. |
| | Session 2 — Edge Computing Fundamentals | Theory | Cloud AI vs. Edge AI. Latency, privacy, and power trade-offs. Why inference on-device changes everything for robotics and embedded systems. |
| | Session 3 — Embedded Systems with Arduino Q | Practical | Hands-on with the Arduino Q board. IDE setup, uploading code, reading sensors, controlling outputs, serial monitor debugging. |
| | Session 4 — TinyML Simplified | Theory + Practical | What TinyML is and how it works. Using Edge Impulse to collect data, train a model, and deploy it to Arduino Q — without needing to write ML code from scratch. |
| | Session 5 — Guided Physical AI Project | Theory + Practical | Follow a complete guided project as a group. Experience the full pipeline: sensor data → Edge Impulse → trained model → Arduino Q → actuator response. |
| | Session 6 — Project Ideation & System Design | Team/Design | Teams form and brainstorm their Day 2 project. Define the problem, choose sensors and actuators, sketch the system architecture (Sensor → Model → Decision → Actuator). |
| **DAY 2 — Build & Showcase** | Recap & Architecture Review | Discussion | Quick recap of Day 1 concepts. Teams present their system design for feedback before building. |
| | Build Phase | Practical | Teams build their Physical AI systems. Facilitators help debug hardware and code issues. |
| | Testing & Documentation | Practical | Rigorous testing. Document the project on [hackster.io](https://hackster.io) or [Arduino Project Hub](https://projecthub.arduino.cc) with photos, code, and a description. |
| | Project Demonstrations | Presentation | Each team presents their working system. Live demo + explanation of architecture and challenges. |
| | Awards & Certification | Awards | Best projects recognised. Certificates issued to all participants (Salman × Robu × Arduino). |
